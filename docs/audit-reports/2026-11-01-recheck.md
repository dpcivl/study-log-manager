# 보안 감사 재확인 (2026-11-01)
- 기준 감사: docs/audit-reports/2026-11-01.md (기준 커밋 b1e25b5)
- 결과: SEC-1~4와 감사 minor 11건이 모두 해결됨이다. 새 blocker와 major는 없다.
- 판정은 security가 코드를 읽어 내렸고, qa가 실제 uvicorn으로 주요 항목을 재현했다.

| SEC 번호 | 판정 | 근거 |
| --- | --- | --- |
| SEC-1 | 해결됨 (해석 변경) | `PUBLIC_DEPLOY=true`면 비었거나 공백뿐이거나 짧은 값으로 시작을 거부하고 원인을 CRITICAL로 남긴다. 값은 로그에 없다. 감사 원문은 무조건 거부였으나, 사용자의 로컬 값이 약해 켜진 경우로 한정했다. 꺼지면 경고만 남긴다. |
| SEC-2 | 해결됨 (해석 구체화) | 상한 1MiB, 초과 413이다. 선언 크기와 실제 읽은 바이트를 모두 검사하고 인증과 415보다 먼저 돈다. `password` 1024자 초과는 비교 없이 401이고 시도로 센다. 본문을 읽지 않는 `/api/logout`은 스트림 본문에서 204다. 메모리 위험은 없다. |
| SEC-3 | 해결됨 | `PUBLIC_DEPLOY=true`면 요청과 무관하게 `Secure`가 붙고 로그아웃도 같다. HSTS도 앱이 보낸다. |
| SEC-4 | 해결됨 (범위 변경) | 앱은 `request.client.host`만 읽는다. 해결은 uvicorn 옵션과 running.md 규칙으로 했다. qa가 신뢰하지 않는 주소에서는 헤더를 바꿔도 6번째가 429이고, 헤더를 믿는 설정에서는 잠금이 풀리는 것을 실행으로 확인했다. 실제 프록시 환경은 배포 위치가 정해진 뒤 확인한다. |
| minor 화면 id | 해결됨 | 로그인 검사가 경로 검증보다 먼저 돌아 302다. |
| minor request.url | 해결됨 | 앱은 scope만 읽는다. 끝 슬래시 리다이렉트도 껐다. |
| minor NUL | 해결됨 (확대) | 제어 문자 전반을 저장 필드와 `tag` 쿼리에서 거부한다. |
| minor 강제 로그아웃 | 해결됨 (방식 변경) | `Sec-Fetch-Site: cross-site`면 403이다. 헤더가 없는 구형 브라우저는 통과한다. |
| minor 실패 제한 단위 | 해결됨 (위험 수용) | IPv6는 /64로 묶고 잠금은 가장 늦게 지운다. 전역 상한은 주인까지 잠글 수 있어 두지 않았다. 주소가 많은 공격자는 막지 못하며 running.md에 적었다. |
| minor 보안 헤더 | 해결됨 | 모든 앱 응답에 붙는다. 지휘자가 브라우저에서 CSP 위반이 없음을 확인했다. 이미지는 https와 data:를 허용한다. |
| minor Cache-Control | 해결됨 | `/api` 전체에 `no-store`다. HTML에는 두지 않았다. |
| minor hide_parameters | 해결됨 | 모든 엔진에 켜져 있다. |
| minor pytest | 해결됨 | pytest를 9로 올리고 운영 의존성을 나눴다. pip-audit 0건. |
| minor 잠금 파일 | 해결됨 | requirements-prod.lock에 해시로 잠갔다. |
| minor .gitignore | 해결됨 | `.env` 변형, DB, 부속 파일, 백업 확장자를 더했다. |

## 남은 info

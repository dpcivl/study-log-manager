## 해석 기록
- F1: 공백만 있는 이름은 비어 있는 것으로 보고 422로 거부한다. 그 밖의 이름은 받은 그대로 저장한다.
- F1: PATCH에서 name, background, started_on에 null을 보내면 422다. target_date에 null을 보내면 목표일을 지운다.
- F1: GET /api/subjects는 5절 표와 예시대로 `{items}`만 돌려준다(페이지 없음). 공통 규칙의 total·page·limit은 페이지를 나누는 목록에만 붙는다.
- F1: API 경로의 id가 정수가 아니거나 범위 밖이면 없는 자원으로 보고 404다(422가 아니다).
- F2: 목록은 항상 studied_on 내림차순, 같은 날은 id 내림차순이다. "목록 맨 위"는 가장 최근 날짜로 추가했을 때의 결과이며, 지난 날짜를 추가하면 날짜 순서 자리에 들어간다.
- F2: 미래 날짜도 저장할 수 있다. 다만 최근 7일 합계에는 들어가지 않는다(오늘 포함 7일은 KST 오늘-6일 ~ 오늘).
- F2: PATCH에서 studied_on, minutes, memo에 null을 보내면 422다. minutes는 정수만 받는다(60.5, "60", true는 422).
- F2: minutes의 15 단위는 화면 입력 편의이며 API는 1~1440 정수를 모두 받는다.
- F2: 없는 기록의 404 메시지는 "기록을 찾을 수 없습니다"다.
- F3: 공백만 있는 제목은 비어 있는 것으로 보고 422다. 그 밖의 제목은 받은 그대로 저장한다.
- F3: 태그는 앞뒤 공백을 지우고 소문자로 바꾼 뒤, 같은 값은 처음 하나만 남긴다(순서 유지). 1~30자와 최대 20개는 이 정리를 마친 값으로 검사한다. 정리 뒤 빈 태그는 422다.
- F3: PATCH에서 kind, title, body, tags, is_open에 null을 보내면 422다.
- F3: PATCH는 보낸 필드가 하나라도 있으면 updated_at을 갱신한다. 빈 객체 PATCH는 200이고 아무것도 바꾸지 않는다.
- F3: 없는 노트의 404는 "노트를 찾을 수 없습니다", 없는 주제에 노트를 만들 때의 404는 "주제를 찾을 수 없습니다"다.
- F3: 문단 안의 한 줄 바꿈은 화면에서도 줄을 유지한다(목업의 `<br>`과 같다). 설계 문서에는 없어 목업을 따른다.
- F3: 작업 목록(`- [x]`, `- [ ]`)의 체크 상태는 화면에 보여야 한다. 입력 요소는 계속 금지하므로 글자 기호로 보인다.
- 공통: 요청 본문의 깨진 JSON과 객체가 아닌 본문은 422 `fields.request`로 돌려준다(Note `body` 필드와 구분).
- F4: 응답의 `tags`는 문자 코드 순으로 정렬한다(영문 다음 한글). 목업의 `sort()`와 같고, 5절 예시의 순서는 예시일 뿐이다.
- F4: `q`는 앞뒤 공백을 지우고, 비어 있으면 조건이 없는 것으로 본다. 대소문자 무시는 SQLite LIKE 기준이라 ASCII 글자에 적용된다(한글은 대소문자가 없다). `%`, `_`는 글자 그대로 찾는다.
- F4: `open=true`만 조건이다. `open=false`나 생략은 조건 없음이고, 불리언이 아닌 값은 422다.
- F4: `tag`는 저장된 값과 정확히 일치해야 한다. 쿼리 값을 소문자로 바꿔 주지 않는다. 여러 개면 모두 포함해야 한다.
- F4: 같은 updated_at이면 id 내림차순이다.
- F4: "조건에 맞는 노트가 없습니다"는 노트가 아예 없을 때도 보인다(목업과 같다).
- F4: `q`는 앞뒤 공백을 지운 뒤 200자 이내이고 NUL 문자가 없어야 한다. 아니면 422 `fields.q`다. 설계에 없어 8절 입력 검증 문장에 따라 정했다.
- F4: `tag`는 최대 20개, 각 1~30자다(4절 태그 제한과 같다). 벗어나면 422 `fields.tag`다.
- 공통: 처리되지 않은 예외는 500 `{"error":{"code":"internal_error","message":"서버 오류가 발생했습니다"}}`로 돌려준다(5절 "오류 응답은 모두 이 모양").
- F6: 공부 기록은 한 건당 한 줄이다(같은 날 두 건이면 두 줄). 날짜 오름차순, 같은 날은 id 오름차순이다. 합치지 않는다(목업과 같다).
- F6: 시간 표기는 화면의 formatHours와 같은 계산이다(분을 시간으로 바꿔 소수 첫째 자리까지 반올림, 90분은 1.5h, 60분은 1h).
- F6: 노트가 없는 유형도 섹션 제목은 남긴다. 태그가 없으면 "태그:" 줄을 뺀다. 본문이 비면 본문 줄이 없다.
- F6: 노트 본문은 한 글자도 바꾸지 않는다. 목업의 "빈 줄 3개 이상 줄이기"는 본문에 적용하지 않는다. 코드 블록 내용이 바뀌기 때문이다.
- F6: 파일 이름은 주제 이름에서 `/`, `\`, `..`를 지운 값이다. 지우고 나서 비면 `subject.md`다. `filename*=UTF-8''` 인코딩만 쓴다.
- F6: 같은 시각의 노트는 id 오름차순이다.
- F6: 노트 제목의 줄바꿈 문자는 내보낼 때 공백으로 바꿔 `## 제목`이 한 줄이 되게 한다. 저장된 값은 바꾸지 않는다.
- SEED: 시드 원문은 저장소에 없어 설계 세션의 첫 메시지에 붙여 넣은 노트를 쓴다. 공부 기록 합계 360분과 4일이 5절 예시와 같다.
- SEED: 같은 이름의 주제가 이미 있으면 아무것도 바꾸지 않고 건너뛴다(중복 생성 없음, 기존 데이터 수정 없음).
- SEED: 사용자 글은 고치지 않고 그대로 넣는다(원문의 오타 포함). 후기의 항목들은 노트 6건에 맞춰 "코딩팡 사용" 한 건에 모은다.
- SEC: 사용자 지시로 설계 보완 질문 12개를 지휘자가 정한다. design.md는 고치지 않고 여기에 남긴다.
- SEC-1: `PUBLIC_DEPLOY` 설정 하나로 공개 배포를 표시한다. 켜면 `SECRET_KEY` 32자, `APP_PASSWORD` 12자 미만이거나 공백뿐일 때 시작을 거부한다. 끄면(기본) 시작은 하되 경고를 로그에 남긴다. 사용자의 로컬 값이 약해 무조건 거부하면 서버가 멈추기 때문이다.
- SEC-2: 요청 본문 상한은 1MiB이고 초과는 413 `payload_too_large`다. `password`는 1024자를 넘으면 비교 없이 401이고 시도 횟수에 넣는다.
- SEC-3: 쿠키 `Secure`는 `PUBLIC_DEPLOY`가 켜지면 항상 붙는다. 꺼져 있으면 지금처럼 https 요청에만 붙는다. HSTS는 켜졌을 때 응답 헤더로 보낸다.
- SEC-4: 프록시 신뢰는 uvicorn 옵션으로 정하고 running.md에 규칙을 적는다. 배포 위치는 정하지 않는다.
- SEC-1: 최소 길이는 앞뒤 공백을 뺀 길이로 센다.
- SEC-2: 운영 실행은 `--http h11`로 정한다. httptools는 헤더 누적 상한이 없을 수 있다. 앞단 프록시에도 헤더 크기, 본문 시간, 연결 수 제한을 둔다.
- SEC-5: `/openapi.json`은 끈다. `/static/*`은 공개로 둔다. 미로그인의 415, 400, 405, 없는 주소 응답은 지금 동작을 유지한다. 정수가 아닌 화면 id는 미로그인이면 302다. 로그아웃은 `Sec-Fetch-Site: cross-site`면 403이다. 전역 실패 상한은 두지 않는다(공격자가 주인까지 잠글 수 있다). IPv6는 /64로 묶는다.
- SEC-6: 외부 이미지는 https만 허용하고 `Referrer-Policy: no-referrer`를 둔다. 운영은 단일 워커로 한다. 토큰 유출 절차는 `SECRET_KEY` 교체다.
- SEC-5: 한 줄 필드(name, title, memo, 태그, `tag` 쿼리)는 제어 문자를 거부하고 여러 줄 필드(background, body)는 NUL과 줄바꿈·탭 밖의 제어 문자를 거부한다(422). 태그의 쉼표도 거부한다. password는 제외한다. 이에 따라 F6의 "줄바꿈 든 이름" 테스트 기대를 422로 바꾼다.
- SEC-5: 로그아웃의 403 응답은 `{"error":{"code":"forbidden","message":"다른 사이트에서 보낸 요청입니다"}}`다.
- SEC-6: 잘못된 UTF-8 본문은 로그인 전이면 401, 로그인 후면 422 `fields.request`다. 영어 400을 내지 않는다.
- SEC-6: 저장 금지(`Cache-Control: no-store`)는 `/api`에만 둔다. HTML은 뒤로 가기 동작을 위해 두지 않는다.
- SEC-5: 태그는 앞뒤 공백(탭, 줄바꿈 포함)을 먼저 지운 뒤 안쪽의 제어 문자와 쉼표를 검사한다(5절 "공백 trim 저장"과 F3 동작 유지).
- SEC-6: 405의 `Allow`는 프레임워크가 주는 값을 그대로 쓴다. 헤더가 있으면 된다.
- SEC-5: 제어 문자나 쉼표로 거부되면 길이 문구 대신 그 이유를 말하는 문구를 쓴다.
- SEC-5: 쿼리 `tag`의 쉼표도 거부한다. 끝 슬래시 리다이렉트는 끈다(`/api/subjects/`는 404).
- SEC: 감사 보고서는 push하지 않는다. 공개 여부는 사용자가 정한다.
- 공통: page는 1 이상, limit은 1~100 정수다. 벗어나면 422 validation_error다(100으로 잘라 주지 않는다).
- F5: "틀린 비밀번호 5회 연속이면 60초 동안 429"는 5번째 틀린 시도까지 401이고, 6번째 시도부터 60초 동안 429로 읽는다(5절 "5회 연속 실패 후 60초"). 목업이 5번째에서 잠금 문구를 보이는 것과는 다르며 API 기준을 따른다.
- F5: 로그인 상태에서 GET /login은 /로 "이동"이면 되므로 리다이렉트 상태 코드(302·303·307)를 고정하지 않는다. 미로그인 리다이렉트는 302로 고정한다.
- F7: 렌더는 성공해도 읽을 수 없는 깊은 인용은 F7 범위로 본다. 인용은 1~3겹까지 전과 같고, 4겹부터는 들여쓰기를 더하지 않는다. 정화가 예외 없이 문서 조각이 아닌 값을 돌려주면 정화 실패로 본다.
- F10: "환경 변수와 절대 경로는 그대로 쓴다"는 환경 변수가 `.env`보다 우선한다는 뜻이다. 환경 변수로 준 상대 경로 `DATABASE_URL`도 프로젝트 폴더 기준으로 바꾼다.
- F10: 시작할 때 쓸 수 없는 기존 DB(읽기 전용 파일)는 "DB를 쓸 수 없음"으로 보고 시작 실패다.
- F10: "SQLAlchemy가 던진 DB 오류"는 드라이버 오류(DBAPIError와 하위 클래스)다. 코드 버그성 SQLAlchemy 예외는 500 `internal_error`로 둔다.
- F10: "DB를 쓸 수 없음"에는 파일과 그 폴더가 모두 들어간다. 롤백 저널을 만들지 못하면 쓸 수 없기 때문이다.
- F10: 시작 때 새로 만드는 DB 폴더는 소유자 전용(700), 새 DB 파일은 소유자 읽기·쓰기(600)다. 이미 있는 폴더와 파일의 권한은 바꾸지 않는다.
- F10: `DATABASE_URL`의 쿼리나 포트 값이 틀린 것도 "`DATABASE_URL` 형식이 틀림"이다.
- F10: 시드 스크립트도 앱과 같은 저장소 열기 경로를 쓴다. 먼저 돌려도 새 폴더는 700, 새 파일은 600이다.
- F11: 내보내기의 "비정상 응답"은 2xx인데 Content-Type이 `text/markdown`이 아니거나 204인 경우다. 파일을 만들지 않고 "서버 응답을 해석할 수 없습니다"를 보인다.
- F8: `next` 허용 경로 검사는 서버가 한다. GET /login은 `<section id="s1">`의 `data-next`에 검사를 통과한 경로를 넣고, 아니면 빈 값을 넣는다. 세션 만료 안내 `#login-expired`는 `expired=1`일 때만 `hidden` 없이 내려준다. 로그인 스크립트는 `data-next`만 쓴다. 허용 경로는 쿼리나 조각이 없는 정확한 경로뿐이다.
- F8: id에 앞자리 0이 붙은 경로는 `next`에서 거부한다. 형식이 다른 경로다.
- F8: 입력을 건드리지 않았으면 페이지를 떠날 때나 401 때 초안을 덮어쓰지 않는다. 안내 줄이 떠 있는 동안 변경 없이 나가도 고르지 않은 초안은 남긴다.
- F8: 초안의 `kind`가 값 범위 밖이면 복원할 때 지금 유형을 둔다. title과 body가 문자열이 아니면 손상으로 보고 지운다.
- F8: 안내 줄이 떠 있는 동안에는 초안 키를 쓰지 않는다. "복원"이나 "버리기"를 고른 뒤부터 쓴다. "저장"을 누른 것도 지금 입력을 고른 것으로 본다. 입력을 건드렸으면 그때 안내 줄을 닫고 지금 입력을 초안에 쓴다. 그 밖의 새 입력은 이탈 경고로 보호한다.
- F8: 브라우저 캐시에서 복원된 S4는 페이지를 새로 읽는다. 초안은 저장소에 있으므로 안내 줄로 이어진다.
- F9: `expected_updated_at`의 형식 오류에는 null, 문자열이 아닌 값, `YYYY-MM-DDTHH:MM:SSZ` 모양이 아닌 값, 달력에 없는 날짜와 시각이 모두 들어간다. 문구는 `fields.expected_updated_at`의 약속 문구 하나다. 저장되지 않는 값이라 `model_dump`나 응답에 나오지 않는다.

- F9: 검사와 쓰기 사이의 경합은 받아들인다. 설계가 받아들인 "같은 1초 안의 두 저장"과 같은 성격이고 사용자는 1명이다.

## 해석 기록
- F1: 공백만 있는 이름은 비어 있는 것으로 보고 422로 거부한다. 그 밖의 이름은 받은 그대로 저장한다.
- F1: PATCH에서 name, background, started_on에 null을 보내면 422다. target_date에 null을 보내면 목표일을 지운다.
- F1: GET /api/subjects는 5절 표와 예시대로 `{items}`만 돌려준다(페이지 없음). 공통 규칙의 total·page·limit은 페이지를 나누는 목록에만 붙는다.
- F1: API 경로의 id가 정수가 아니거나 범위 밖이면 없는 자원으로 보고 404다(422가 아니다).
- F2: 목록은 항상 studied_on 내림차순, 같은 날은 id 내림차순이다. "목록 맨 위"는 가장 최근 날짜로 추가했을 때의 결과이며, 지난 날짜를 추가하면 날짜 순서 자리에 들어간다.
- F2: 미래 날짜도 저장할 수 있다. 다만 최근 7일 합계에는 들어가지 않는다(오늘 포함 7일은 KST 오늘-6일 ~ 오늘).
- F2: PATCH에서 studied_on, minutes, memo에 null을 보내면 422다. minutes는 정수만 받는다(60.5, "60", true는 422).
- F2: minutes의 15 단위는 화면 입력 편의이며 API는 1~1440 정수를 모두 받는다.
- F2: 없는 기록의 404 메시지는 "기록을 찾을 수 없습니다"다.
- 공통: page는 1 이상, limit은 1~100 정수다. 벗어나면 422 validation_error다(100으로 잘라 주지 않는다).
- F5: "틀린 비밀번호 5회 연속이면 60초 동안 429"는 5번째 틀린 시도까지 401이고, 6번째 시도부터 60초 동안 429로 읽는다(5절 "5회 연속 실패 후 60초"). 목업이 5번째에서 잠금 문구를 보이는 것과는 다르며 API 기준을 따른다.
- F5: 로그인 상태에서 GET /login은 /로 "이동"이면 되므로 리다이렉트 상태 코드(302·303·307)를 고정하지 않는다. 미로그인 리다이렉트는 302로 고정한다.

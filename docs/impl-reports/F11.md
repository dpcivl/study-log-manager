## 한 일
공통 요청에 15초 시간 제한을 넣었고, 2xx인데 JSON이 아닌 응답을 실패로 돌린다. 로그인과 내보내기도 같은 규칙을 쓴다.
로그아웃 실패, 요약 갱신 실패 문구, 로그인 잠금의 남은 초, 서버 문구 표시를 넣었다.
화면 주소의 404와 처리되지 않은 예외는 JSON 대신 오류 화면 S6으로 보인다.

## 이번에 정한 해석
- F11: 내보내기의 "비정상 응답"은 2xx인데 Content-Type이 `text/markdown`이 아니거나 204인 경우다. 파일을 만들지 않고 "서버 응답을 해석할 수 없습니다"를 보인다.

## 브라우저 확인 (지휘자)
- 쓰기 요청 무응답: 15.7초 뒤 "응답을 받지 못했습니다..." 문구, 버튼 재활성
- 읽기 요청 무응답: 15.8초 뒤 "서버 응답이 없습니다..." 문구
- S2, S4의 200 비JSON: "서버 응답을 해석할 수 없습니다", 입력 유지, 버튼 재활성. 내보내기 200 HTML과 204는 파일을 만들지 않음
- 로그아웃 실패: S2에 머물고 문구 표시
- 요약 갱신 실패와 다음 성공 때 문구 사라짐
- 로그인 잠금: 60초에서 4초 뒤 56초, 대기 중 버튼 꺼짐, 서버 문구 표시
- S6: 문구, 링크, 스크립트 없음

## 남은 지적 (minor, info)
- (minor) src/app/static/js/common.js: 데이터를 기대하는 요청의 204나 필드가 다른 객체는 성공으로 지나간다. 지금 서버는 이런 응답을 내지 않는다 - reviewer
- (minor) tests/test_resilience.py: `/api`, `/static`, `/apix` 같은 S6 경로 경계 시험이 없다. QA가 HTTP로 확인했다 - reviewer
- (minor) src/app/static/js/common.js 등: 도달하지 않는 분기와 겹치는 코드가 있다 - reviewer
- (info) F11 완료 기준 5개 중 S6만 자동 시험이 있고 나머지는 브라우저 확인에 의존한다 - reviewer
- (info) 로그인 시간 초과에도 "저장되었는지 확인한 뒤" 문구가 나온다. 설계의 "GET 외" 문구와 같다 - reviewer
- (info) HEAD 요청은 S6이 아니라 JSON이다. 설계와 맞다 - qa
- (info) 로그아웃 뒤 뒤로 가기로 S2가 메모리에서 복원되면 이전 목록이 보일 수 있다. 새 데이터는 얻지 못한다 - security

## 사용자 테스트 목록

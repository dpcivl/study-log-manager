## 사용자가 할 일
1. 시드를 넣는다. 실제 DB는 건드리지 않았으므로 직접 실행해야 데이터가 들어간다.
2. 각 보고서의 사용자 테스트 목록을 확인한다.
3. 작업 브랜치 `fix/mockup-study-sessions`를 `main`에 합칠지 정한다. push는 하지 않았다.

## 설계 문서에 없어 정한 것
전체 목록은 [impl-progress.md](../impl-progress.md)의 해석 기록에 있다. 설계와 다르게 느낄 수 있는 것만 적는다.
- 틀린 비밀번호는 5번째까지 401이고 6번째부터 429다. 목업은 5번째에 잠금 문구를 보였다.
- 문단 안 한 줄 바꿈은 화면에서 유지한다.
- 작업 목록의 체크 상태는 ☑ ☐ 글자로 보인다.
- 검색어는 200자, 태그 조건은 20개까지다. 대소문자 무시는 영문에 적용된다.
- 내보내기에서 공부 기록은 같은 날이어도 합치지 않고 노트 본문은 그대로 둔다.
- 처리되지 않은 예외는 500 `internal_error`로 돌려준다. 깨진 JSON은 422 `fields.request`다.

## 공개 배포 전에 처리할 것
로컬에서 혼자 쓸 때는 문제가 없고, 인터넷에 열기 전에 필요하다. 지금은 minor나 info로 남겨 두었다.
- 프록시 설정: `--forwarded-allow-ips` 없이 프록시 뒤에 두면 모두 한 IP로 묶여 잠금이 공유되고 쿠키에 `Secure`가 빠진다. 방법은 [running.md](../service/running.md)에 있다.
- 요청 본문 크기 상한: 로그인 없이도 POST 본문 전체가 메모리에 읽힌다. 상한 없는 앞단으로 배포하면 major로 본다.
- 보안 헤더: CSP, `X-Frame-Options`, `Cache-Control`이 없다.
- `/openapi.json`이 로그인 없이 열린다.
- DB 오류 메시지에 노트 내용이 들어가 로그에 남을 수 있다(`hide_parameters`).
- 비밀번호와 키의 최소 길이 검사가 없다.

## 확인하지 못한 것
- 실제 파일 저장: 내보내기는 파일 이름과 내용을 가로채 확인했고 디스크 저장은 보지 않았다.
- iOS Safari, Firefox: 확인하지 않았다. 폰 내려받기와 뒤로 가기 뒤 저장 버튼을 직접 봐야 한다.
- 뒤로 가기 복원: 저장 버튼이 다시 켜지는지는 코드 읽기로만 확인했다.
- 30일 세션 만료: 자동 테스트가 없다. 60초 잠금 해제는 QA가 실제로 기다려 확인했다.

## 이번에 정한 해석
- F4: 응답의 `tags`는 문자 코드 순으로 정렬한다(영문 다음 한글). 목업의 `sort()`와 같고, 5절 예시의 순서는 예시일 뿐이다.
- F4: `q`는 앞뒤 공백을 지우고, 비어 있으면 조건이 없는 것으로 본다. 대소문자 무시는 SQLite LIKE 기준이라 ASCII 글자에 적용된다(한글은 대소문자가 없다). `%`, `_`는 글자 그대로 찾는다.
- F4: `open=true`만 조건이다. `open=false`나 생략은 조건 없음이고, 불리언이 아닌 값은 422다.
- F4: `tag`는 저장된 값과 정확히 일치해야 한다. 쿼리 값을 소문자로 바꿔 주지 않는다. 여러 개면 모두 포함해야 한다.
- F4: 같은 updated_at이면 id 내림차순이다.
- F4: "조건에 맞는 노트가 없습니다"는 노트가 아예 없을 때도 보인다(목업과 같다).
- F4: `q`는 앞뒤 공백을 지운 뒤 200자 이내이고 NUL 문자가 없어야 한다. 아니면 422 `fields.q`다. 설계에 없어 8절 입력 검증 문장에 따라 정했다.
- F4: `tag`는 최대 20개, 각 1~30자다(4절 태그 제한과 같다). 벗어나면 422 `fields.tag`다.
- 공통: 처리되지 않은 예외는 500 `{"error":{"code":"internal_error","message":"서버 오류가 발생했습니다"}}`로 돌려준다.

## 한 일
DB 오류를 503 `storage_busy`와 `storage_unavailable`로 나눴고, 시작 실패를 "시작 실패:" 한 줄과 0이 아닌 종료 코드로 알린다.
`.env`와 상대 경로 DB를 프로젝트 폴더 기준으로 고정했고, 빈 DB를 새로 만들면 경로가 든 경고를 남긴다.
새로 만드는 DB 폴더는 700, 파일은 600이며 시드도 같은 경로를 쓴다. `APP_PASSWORD`나 `SECRET_KEY`가 비면 로그인은 500이다.

## 이번에 정한 해석
- F10: "환경 변수와 절대 경로는 그대로 쓴다"는 환경 변수가 `.env`보다 우선한다는 뜻이다. 환경 변수로 준 상대 경로 `DATABASE_URL`도 프로젝트 폴더 기준으로 바꾼다.
- F10: 시작할 때 쓸 수 없는 기존 DB(읽기 전용 파일)는 "DB를 쓸 수 없음"으로 보고 시작 실패다.
- F10: "SQLAlchemy가 던진 DB 오류"는 드라이버 오류(DBAPIError와 하위 클래스)다. 코드 버그성 SQLAlchemy 예외는 500 `internal_error`로 둔다.
- F10: "DB를 쓸 수 없음"에는 파일과 그 폴더가 모두 들어간다. 롤백 저널을 만들지 못하면 쓸 수 없기 때문이다.
- F10: 시작 때 새로 만드는 DB 폴더는 소유자 전용(700), 새 DB 파일은 소유자 읽기·쓰기(600)다. 이미 있는 폴더와 파일의 권한은 바꾸지 않는다.
- F10: `DATABASE_URL`의 쿼리나 포트 값이 틀린 것도 "`DATABASE_URL` 형식이 틀림"이다.
- F10: 시드 스크립트도 앱과 같은 저장소 열기 경로를 쓴다. 먼저 돌려도 새 폴더는 700, 새 파일은 600이다.

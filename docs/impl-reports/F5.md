## 이번에 정한 해석
- F5: "틀린 비밀번호 5회 연속이면 60초 동안 429"는 5번째 틀린 시도까지 401이고, 6번째 시도부터 60초 동안 429로 읽는다(5절 "5회 연속 실패 후 60초"). 목업이 5번째에서 잠금 문구를 보이는 것과는 다르며 API 기준을 따른다.
- F5: 로그인 상태에서 GET /login은 /로 "이동"이면 되므로 리다이렉트 상태 코드(302·303·307)를 고정하지 않는다. 미로그인 리다이렉트는 302로 고정한다.

## 남은 지적 (minor, info)
- (minor) src/app/auth.py `request.client.host`, src/app/routers/auth.py `request.url.scheme`: 리버스 프록시 뒤에서 uvicorn `--proxy-headers --forwarded-allow-ips`를 설정하지 않으면 모든 사용자가 프록시 IP 하나로 묶여 남이 5회 틀리면 주인도 잠기고, HTTPS여도 쿠키에 Secure가 빠진다. 배포 위치는 design.md 9절 미결이므로 docs/service에 필수 설정으로 적는다 - security(major로 제기), reviewer(minor)
- (minor) tests/test_auth.py: "60초 동안" 잠금이 풀리는지(59초 429, 60초 뒤 허용, 잠금 직후 retry_after 60)와 30일 지난 토큰이 401인지 확인하는 테스트가 없다. `LoginRateLimiter`의 `clock` 주입이 테스트에 쓰이지 않는다 - reviewer
- (minor) tests/test_auth.py 동시 요청 테스트: 401 개수를 `<= 5`로만 단언해 0개여도 통과한다. `== 5`로 바꾸고 `threading.Barrier`로 `acquire`를 동시에 출발시키는 단위 테스트를 더한다 - reviewer
- (minor) src/app/routers/pages.py: 화면 주소의 id가 숫자가 아니면(`/subjects/abc`) 로그인 검사 전에 FastAPI 검증이 422 JSON을 돌려줘 미로그인이어도 /login으로 가지 않는다 - reviewer
- (minor) src/app/routers/pages.py: `if not is_logged_in(request): return _to_login()` 두 줄이 화면 핸들러 5개에 반복된다. 의존성이나 라우터로 모은다 - reviewer
- (minor) src/app/routers/auth.py `password.encode("utf-8")`: JSON `"\ud800"` 같은 짝 없는 서로게이트가 오면 UnicodeEncodeError로 계약에 없는 500이 나간다(시도 횟수는 소모됨). `errors="surrogatepass"`나 401 처리 - security, reviewer
- (minor) src/app/auth.py `_prune`: 추적 IP가 1만 개에 닿으면 모든 실패 횟수를 통째로 비우고, `_locked_until`은 상한 없이 커진다. 만료된 잠금을 acquire 때 정리하고 오래된 것부터 지운다 - security, reviewer

- (minor) src/app/main.py: `/openapi.json`이 로그인 없이 열린다. `openapi_url=None` - security
- (minor) README.md / docs/service: 실행 명령이 `--reload` 개발용 하나뿐이다. 운영 실행 명령(reload 없음, 프록시 헤더 설정 포함)을 따로 적는다 - security
